# bebu mobile (Flutter)

White-label Flutter client for the bebu platform. One codebase produces every
branded application; the tenant is chosen at build time and everything visual
(name, colours, logo, feature flags, legal links) is fetched from the API at
launch via `GET /api/v1/tenant/config`.

> Status: foundation only. The Flutter SDK was not available in the environment
> that produced this code, so `flutter analyze` / `flutter test` have not been
> run here. Run them first when you open the project.

## Layout

```
lib/
  main.dart                     entry point; reads --dart-define flavor
  app/
    app.dart                    gates the app on tenant config, applies theme
    router.dart                 go_router routes (route names are constants)
    theme.dart                  Material 3 theme from tenant branding
  core/
    config/app_flavor.dart      TENANT_KEY / API_BASE_URL / AUTH_MODE
    network/api_client.dart     Dio client: X-Tenant-Key, bearer, X-Request-Id
    network/api_error.dart      ApiException mirroring the API error envelope
  features/
    tenant/                     public tenant config model + provider
    startup/                    loading / error bootstrap screen
    home/                       placeholder home proving the pipeline
test/                           unit tests (pure Dart, no device required)
```

Feature folders to be added in later stages: `auth`, `callers`, `calls`
(Agora + server-authoritative state), `wallet`, `payments`, `notifications`,
`profile`, `caller_onboarding`.

## Running

Android emulator against a local API (the emulator reaches the host at `10.0.2.2`):

```bash
flutter pub get
flutter run \
  --dart-define=TENANT_KEY=bebu \
  --dart-define=API_BASE_URL=http://10.0.2.2:4180 \
  --dart-define=AUTH_MODE=dev
```

iOS simulator: use `http://127.0.0.1:4180`. Physical devices: use your machine's
LAN IP and add it to `CORS_ORIGINS` only if you also serve a web build.

`AUTH_MODE=dev` is rejected in release builds (`StateError` at startup), the
same way the API rejects dev tokens in production.

## Building another brand

No Dart changes are needed. Create the tenant in the admin console (or via
`POST /api/v1/admin/tenants`), then build with its key:

```bash
flutter build apk --release \
  --dart-define=TENANT_KEY=<tenant-key> \
  --dart-define=API_BASE_URL=https://api.bebuapp.in
```

Per-brand native identity (application id, bundle id, icons, Firebase config
files) is handled with Flutter flavors in `android/` and `ios/`, which are
generated by `flutter create .` and configured in the store-release stage.

## Conventions

- State: Riverpod. No global singletons; everything is a provider.
- Navigation: go_router with named routes; deep links and push payloads target
  route names, never widget classes.
- Networking: only through `ApiClient`. It stamps tenant, auth and request id
  headers and converts error envelopes to `ApiException`.
- Money: coins are integers end to end. Never do arithmetic on floats.
- Calls: the server owns call state and billing. The app renders state and
  sends intents; it never decides what a call costs or when to bill.
